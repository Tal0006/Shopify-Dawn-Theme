# Hebrew storefront handoff

The existing Shopify theme is localized and connected to real store collections. The existing layout, assets and palette are reused. Checkout was not modified, and no commit was made. Existing uncommitted upload repairs are preserved.

## Locales

- `locales/he.default.json` is the only default storefront locale, with 466 translated strings/date formats. It covers every original English storefront key, new catalog labels, sorting, customer status labels, accessibility and theme-controlled validation messages.
- `locales/en.default.json` was renamed to `locales/en.json`. Original English translations are preserved, with matching new keys.
- `locales/he.schema.json` translates the important section/setting labels in the Hebrew Theme Editor. Other editor settings fall back to the existing English schema locale.
- `locales/en.default.schema.json` retains the original editor translations and adds the new section/settings keys.
- Other locale files were preserved. New labels in languages other than Hebrew/English use the default locale until the merchant adds their translations.
- The remote development theme's obsolete English default filename was removed to resolve Shopify's locale-renaming upload conflict. The remote default is now Hebrew.

## Assign collections in Theme Editor

Open Online Store → Themes → Customize for the development theme. In the homepage, open **ניווט לפי קטגוריות** and choose a collection in each category block. Open each **מוצרים מקטגוריה** section to set its heading, optional subtitle, collection, number of products and view-all button. Headings are optional; when blank, the selected collection's title is used.

Four pickers were seeded by matching the live store's collection names: **כביסה**, **ניקיון כללי**, **טואלטיקה**, and **חד פעמי**. The stored picker references are editable configuration; no collection handles or IDs are embedded in Liquid or JavaScript business logic.

There is no collection named **חיטוי** in the store. Create/publish that collection in Shopify Admin, then select it in both the category block and the homepage product section. Alternatively select another appropriate existing collection. This slot is hidden from shoppers until assigned; Theme Editor shows a setup instruction. There are no fake product cards.

Under theme settings → **כל הקטגוריות**, the catalog collection picker is set to the real **כל המוצרים** collection. It controls the theme's catalog/continue-shopping/hero fallback links. The header's own navigation is still supplied by Shopify's selected menu.

## Shopify Admin content and manual setup

1. Check Settings → Languages/Markets and keep Hebrew published and primary where intended. The current preview already serves `lang=he`, `dir=rtl`.
2. Create/select the missing חיטוי collection. Collection names, descriptions, images and product membership are managed in Products → Collections.
3. Select the header/footer/customer-service menus in Theme Editor. Menu titles, nesting and destinations come from Shopify Admin; add category links there if desired. If a menu points to Shopify's built-in all-products collection, it will still include all published Admin products, rather than only the selected catalog collection.
4. Shopify currently contains published **Example product** items and the **Default example products** collection. They are Admin catalog content, not placeholders generated by this theme. They can still appear in unrestricted all-products/search/collection-list views. Unpublish or archive the demos in Admin if they should be removed. The curated homepage contains real Hebrew store products and no example products.
5. Product titles/variants/descriptions/vendors, custom filter names/values, menu labels, page content, policies, discount titles, subscription names and pickup-location names/times remain dynamic Admin content. Existing Latin words/brand names, including MIX in product titles, are not overwritten. Translate any unwanted English there or through Shopify Translate & Adapt.
6. Configure storefront filters through Shopify Search & Discovery. Availability, price and standard vendor/product-type labels are translated by the theme; custom labels/values follow Admin content.
7. Upload the store logo and hero image, edit optional homepage copy, set product shipping/pickup information and configure Instagram/Facebook/WhatsApp/TikTok links through Theme Editor. Old ginger-shot contact details, promotional claims and social embed defaults were cleared; no replacement address, discounts or social URLs were invented.
8. Customer accounts are Shopify-hosted on this store. Their URLs/language follow Shopify account/language settings. Legacy customer sections and their native forms remain available and localized if legacy accounts are used. Checkout remains controlled by Shopify.

## Verification

- Shopify Theme Check: zero errors or warnings.
- `node --test tests/localization.test.cjs`: 4 passing regression tests for default locale, translation coverage, interpolation variables, template references/block types/order and saved numeric range settings.
- JavaScript syntax checks pass.
- Development preview uploads successfully. Homepage, cart, search, collection, product and contact pages return without Liquid or missing-translation errors.
- Browser verification: Hebrew/RTL desktop and mobile output; real product images/cards; no horizontal overflow on tested homepage widths 1280/390; quantity controls; native cart add/update/remove; price sorting; availability/price filtering; Hebrew form validation; recommendation rendering; mobile navigation and controls after a simulated Theme Editor header reload.
- Test cart mutations used an isolated browser profile and were cleared. Contact/newsletter forms were not submitted, and checkout was not entered.
- There are no multi-variant products in the current store to exercise live variant selection. The form requires an explicit choice for non-default variants, and cards link to options rather than blindly posting the first variant.
- Full authenticated legacy account/password workflows were not tested because this store uses hosted accounts and its password route redirects to the storefront. Their dependency/schema checks pass.
